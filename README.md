# ESP32 Power Check

ESP32 Power Check turns a Seeed Studio XIAO ESP32-C3 into a simple remote
power-presence monitor. The board sends authenticated heartbeats to a
[Gatus](https://github.com/TwiN/gatus) server while it has power and network
access. If power is lost and the heartbeats stop, Gatus marks the external
endpoint unhealthy and can send an alert.

The firmware does not measure voltage and does not expose an inbound web
server. Power the board from the circuit or location that you want to monitor.

## How it works

After boot, the device connects to a configured 2.4 GHz Wi-Fi network and sends
a heartbeat immediately. It then repeats the request every 30 seconds:

```text
POST <GATUS_BASE_URL>/api/v1/endpoints/<GATUS_ENDPOINT_KEY>/external?success=true
Authorization: Bearer <GATUS_TOKEN>
```

The request has an empty body. A `200` response resets the firmware's failure
counter. The included Gatus example allows 90 seconds between updates, so one
missed 30-second heartbeat does not immediately mark the endpoint unhealthy.

## Requirements

- Seeed Studio XIAO ESP32-C3
- USB data cable and a computer with access to the board's serial port
- 2.4 GHz Wi-Fi; the ESP32-C3 cannot join 5 GHz-only networks
- A Gatus server reachable from that Wi-Fi network
- Python 3 and the PlatformIO CLI (`pio`)

The PlatformIO environment in [`platformio.ini`](platformio.ini) uses the
Arduino framework and the `seeed_xiao_esp32c3` board definition.

## Configure Gatus

Merge [`gatus-config.example.yaml`](gatus-config.example.yaml) into the Gatus
configuration. Its relevant endpoint is:

```yaml
external-endpoints:
  - name: xiao-power-monitor
    group: building
    token: "replace-with-a-long-random-token"
    heartbeat:
      interval: 90s
    alerts:
      - type: discord
        send-on-resolved: true
        failure-threshold: 3
        success-threshold: 2
```

Replace the token and adapt the alert provider to the Gatus installation. The
example's endpoint key is `building_xiao-power-monitor`, formed from its group
and name. Use that exact key in the device configuration. If the group or name
contains spaces or punctuation, use the key generated by Gatus rather than
assuming the original spelling is preserved.

Reload or restart Gatus after changing its configuration. The endpoint will
remain unhealthy until the device sends its first successful heartbeat.

## Configure the device

Create the local secrets header from the tracked template:

```sh
cp include/secrets.example.h include/secrets.h
```

Edit `include/secrets.h` and set the required values:

```cpp
#define WIFI_SSID          "your-2.4-ghz-network"
#define WIFI_PASSWORD      "your-wifi-password"

#define GATUS_BASE_URL     "https://gatus.example.com"
#define GATUS_ENDPOINT_KEY "building_xiao-power-monitor"
#define GATUS_TOKEN        "replace-with-the-same-token-used-by-gatus"
```

`GATUS_BASE_URL` may have a trailing slash; the firmware removes it before
building the request URL. For HTTPS, use a DNS name present in the server
certificate rather than a bare IP address.

### Optional Wi-Fi networks

Up to two fallback networks can be added. The firmware normally joins the
strongest configured network that is available:

```cpp
#define WIFI_SSID_2     "backup-network"
#define WIFI_PASSWORD_2 "backup-password"
#define WIFI_SSID_3     "third-network"
#define WIFI_PASSWORD_3 "third-password"
```

Use an empty password for an open network.

### HTTPS and NTP

Verified HTTPS is the recommended production configuration. Add the PEM-encoded
issuing root certificate to `include/secrets.h`:

```cpp
#define GATUS_ROOT_CA \
  "-----BEGIN CERTIFICATE-----\n" \
  "...\n" \
  "-----END CERTIFICATE-----\n"
```

The device synchronizes its clock over NTP because certificate validation
requires valid time. The defaults are `pool.ntp.org` and
`time.cloudflare.com`; override them when the network supplies internal NTP
servers:

```cpp
#define NTP_SERVER_1 "ntp1.example.com"
#define NTP_SERVER_2 "ntp2.example.com"
```

For temporary testing only, `#define GATUS_ALLOW_INSECURE_TLS` disables
certificate validation. Without either `GATUS_ROOT_CA` or that explicit
override, the firmware refuses to send to an HTTPS URL. Plain HTTP works but
exposes the bearer token and should only be used on a trusted network.

## Build, flash, and monitor

Run the following commands from this directory:

```sh
pio run
pio run -t upload
pio device monitor
```

The serial monitor is configured for 115200 baud. If PlatformIO cannot select
the correct port automatically, list detected devices and pass the port
explicitly:

```sh
pio device list
pio run -t upload --upload-port /dev/ttyACM0
pio device monitor --port /dev/ttyACM0
```

The port may instead be named `/dev/ttyUSB0`. On Linux, confirm that the current
user can access the device; distributions commonly grant serial access through
the `dialout` or `uucp` group.

If installing PlatformIO in a project-local virtual environment, create it on
the current machine rather than copying an existing `.venv` directory:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade platformio
pio run
```

The `.venv`, `.pio`, and `.platformio` directories are ignored by Git.

## Verify operation

Open the serial monitor and reset the board. Startup output should identify the
chip, reset reason, persistent boot count, heartbeat interval, and whether the
configured link uses HTTP or HTTPS. A healthy device then reports:

- the selected SSID, local IP address, signal strength, and Wi-Fi channel;
- NTP synchronization when required;
- the Gatus heartbeat URL and `http_code=200`;
- uptime, free heap, and network details with each heartbeat.

Confirm in Gatus that `building / xiao-power-monitor` becomes healthy and stays
healthy. To test the complete alert path, disconnect power from the board and
wait longer than the configured Gatus heartbeat interval and alert threshold.

## Recovery behavior

The firmware is designed to run unattended:

- It retries a disconnected Wi-Fi connection every 10 seconds.
- After three failed reconnect attempts, it tries configured networks in order
  instead of relying only on strongest-network selection.
- After 30 failed Wi-Fi attempts (about five minutes), it restarts the ESP32.
- It retries NTP every 60 seconds while the clock is invalid. HTTPS heartbeats
  are deferred until time is valid; HTTP heartbeats can continue.
- After 20 consecutive heartbeat responses other than HTTP `200` (about ten
  minutes), it restarts the ESP32.

The persistent boot counter and reset reason in the serial log help distinguish
power interruptions from recovery restarts.

## Troubleshooting

| Symptom | Checks |
| --- | --- |
| No serial device appears | Use a USB data cable, try another USB port, run `pio device list`, and put the XIAO into bootloader mode if an upload was interrupted. |
| Permission denied opening the port | Check the device ownership and add the user to the distribution's serial-access group, then sign in again. Stop other programs using the port. |
| Wi-Fi never connects | Confirm the SSID is 2.4 GHz, credentials are correct, and signal strength is adequate. Review the visible-network scan in the serial log. |
| Gatus returns `401` or `403` | Ensure `GATUS_TOKEN` exactly matches the token on the corresponding Gatus external endpoint. |
| Gatus returns `404` | Check `GATUS_BASE_URL` and copy the exact generated endpoint key into `GATUS_ENDPOINT_KEY`. |
| HTTPS heartbeat is deferred | Confirm DNS and NTP are reachable and the clock synchronization appears in the serial log. |
| TLS handshake fails | Use a hostname covered by the certificate and install the correct issuing root in `GATUS_ROOT_CA`. Do not use the insecure override in production. |
| `.venv/bin/pio` cannot execute | Delete or move the local ignored virtual environment and recreate it on this machine; virtual-environment launchers contain absolute interpreter paths. |

## Security

`include/secrets.h` contains Wi-Fi credentials, the Gatus bearer token, and
possibly a custom CA certificate. It is excluded by [`.gitignore`](.gitignore)
and must never be committed. Keep the example file populated only with dummy
values, use a long unique Gatus token, prefer verified HTTPS, and rotate any
credential that is accidentally exposed.
